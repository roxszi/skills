# 文献精读与方法学审查

## 这个技能解决什么

读文献的常见失效有三种：复述作者主张而不给判断、把「没报告」说成「没做」、以及把光学或统计现象当成物理量直接引用。本技能把交付拆成「提取」与「审查」两段，强制分开，避免复述冒充分析。

本技能同时管三件事：读多深（档位与成本申报）、读到哪（证据锚点可追溯）、读完给不给判断（方法学审查分级）。

设计渊源：分级与证据强制机制借鉴 Paper-review-kit v0.3.0（MIT，castiel0519/Paper-review-kit）的可校验契约思想，schema 与工作流按化学文献精读场景重造；v1.0.0 起由 paper-reading-tiers 与本技能改造线融合而来。

## 0 交付形态与档位

先定形态，再动手。形态由用户表述决定，不由文件长度决定。

| 档位 | 触发语 | 交付 | 阅读深度 |
|---|---|---|---|
| **速览** | 明确说「快速看一眼」「大概说说」「先给个印象」「读文献」「这篇讲了什么」 | 会话内速览 ≤400 字，含七项：阅读深度声明、主旨一句（这篇解决什么问题＋用什么手段＋核心结果）、方法一句、关键数值一句、局限一句、未读范围声明、升级建议 | 摘要＋图表标题＋结论段 |
| **精读（默认）** | 「读一下」「看一下」「精读」「深入读」「靠谱吗」「能不能支撑我的方案」「对比几篇」 | 第 7 节结构（主旨句＋七章） | 按第 2 节顺序通读；超长文先走第 2 节成本申报 |

精读后的延伸交付（用户明示需要时执行，不是独立档位）：

- 成文报告——单点技术交宿主写作类技能成文；多篇综述走第 9 节。
- 条目存档——第 8 节的宽泛落盘契约。宿主已有文献管理方案时优先走宿主方案；没有时用本契约兜底，并按第 8 节向用户说明其定位。

档位判定原则：

- 用户未明说档位时，按触发语就近判定；仍拿不准 → 一句话问清（「要速览还是精读？」），不默认跳档。
- **只升不降**：用户要精读而实际只读到摘要，申报 abstract_only 并说明原因（付费墙、扫描件无文本层、转换失败、用户要求快速）。禁止以速览冒充精读。
- 速览后发现值得深入，可升级为精读，但须告知用户「我升级到精读了」。
- 同一会话同批次多篇：档位逐篇独立判定，逐篇交付，不合并档位。
- 存档条目是后续综述的事实源：写错一处，未来所有综述都被污染。跨会话续做的条目从第 8 节草稿转正，禁止凭后续会话记忆重写已核实内容。

## 1 取原文

### 1.0 宿主适配表（本表是全技能唯一的工具名出处）

本技能正文与 assets 一律只写「能力」，宿主工具名只允许出现在本表。迁移到新宿主时只改本表，其余内容不动。

| 能力 | 能力要求 | 各宿主工具名（择一即可） |
|---|---|---|
| 浏览器 JS 执行 | 在已打开的文章页 tab 内运行任意 JS，支持大结果分块落盘 | EasyClaw：browser-tool 的 run-code；Cherry：`mcp__browser__execute`；其他宿主：等价 CDP 执行工具 |
| 网页抓取 | 服务器侧取 HTML 文本 | EasyClaw：web_fetch；Cherry：`mcp__cherry_tools__web_fetch`；其他宿主：Node fetch 脚本 |
| 文档转换 | PDF／docx → 文本或 markdown | EasyClaw：pdf / docx 技能；Cherry：内置转换；其他宿主：pdftotext 等命令行工具 |
| 脚本运行时 | 运行 `scripts\*.mjs`（零外部依赖 ESM） | node ≥ 20 或 bun 均可，按宿主实际可用者执行 |
| 子会话（仅触发评测用） | 批量向子会话投递探针并回收答案 | EasyClaw：sessions_spawn；Cherry：session_create；无则人工逐条探针 |

### 1.1 本地文件

看到用户给出工作区外的路径（`D:\文献\`、`C:\Users\...\Downloads\` 等），直接先复制到会话工作区再转换，不要先试转换再报错——文档转换能力通常只接受会话工作区、智能体数据目录、或本会话附件路径，以其自身约束为准。

转换后按返回的临时 md 路径分片读取（单次读取上限通常约 50KB／2000 行，超限会被截断）。一篇长文献通常需要两三次读加一次尾部确认，**不要整篇一次性载入**——截断处往往正好是结论段。

扫描件或纯图片 PDF 无文本层，本流程不适用，直接报告。

转换完成后删掉工作区内的文件副本，删除范围只限本轮复制进工作区的文件，用户原始文件一律不删。转换产出的 md 保留到本轮交付结束。同一会话内再复制同名文件直接覆盖，不改名另存。

### 1.2 只有 DOI 或链接

走出版商全文链路，资产在 `assets\`：

| 需求 | 资产 | 说明 |
|---|---|---|
| PDF 原版 | `assets\pdf-fetch.md` | 三层链路：OA 直取 → 同域 fetch → 原生下载。原生下载前必须先发消息提醒用户放行 |
| 网页正文 | `assets\publisher-extract.md` | 跨站通用流程，浏览器内执行 JS 提取正文 |
| ACS 专化 | `assets\acs-extract.js` | `.article-body` 命中时用，失效即回通用流程 |

浏览器侧执行环境见 §1.0 适配表「浏览器 JS 执行」；无浏览器时用「网页抓取」能力取 HTML 作回退。返回体大时分块取，再落盘。

红线：只取 OA 或已订阅内容（机构登录态／校园网 IP 授权）；Sci-Hub 类第三方转载渠道默认关闭，仅用户显式授权才使用。

### 1.3 拿不到全文

降级继续，不阻塞主线：read_status 申报 abstract_only 或 partial_read，写明缺哪部分、为什么缺、能补的路径是什么。摘要级信息只按摘要陈述，不得引用正文细节、图表数据、补充材料。

## 2 通读与成本申报

按此顺序定位，不必从第一页读到最后一页：标题与摘要 → 引言（问题定义、已有方案为何不够用，是交付第一章的素材来源）→ Methods → Results 逐图看图注 → Discussion → Conclusion → 补充信息声明。

图表里的数值往往只存在于图中，PDF 转文本取不到。遇到关键数值来自图时，按第 6 节标注来源。

开读前先侦察正文规模（字符数、图表数），按三档定级：轻 <3 万字符／中 3–10 万／重 >10 万。

- 轻档与中档直接开跑，交付首行带一句规模说明（如「本文 4.5 万字符，全文精读」）。
- 重档先出申报卡，等用户拍板二选一，用用户的语言说清选项与代价：「全文精读（最完整，耗时最长）」或「核心精读（摘要＋引言＋结论＋方法学关键章节＋全部图表，快但交付时明确标注覆盖范围）」。用户明确「好好读」且接受重档成本时直接执行全文精读。用户不回复不默认开跑全文精读。
- 核心精读交付时开头用自然语言标注覆盖范围（如「本次为部分精读：已读第 1、4、7 节与全部图表标题，跳过第 2、3、5、6 节」），阅读深度如实申报，禁止冒充全文已读。

成本申报是透明化，不是降档工具。

## 3 read_status 四态与证据锚点

阅读深度如实申报，写进交付首行：

- `full_read`——已读全文（正文＋图表）
- `partial_read`——已读部分章节或段落，须列出已读与跳过的章节清单
- `abstract_only`——仅摘要，或摘要加个别段落
- `missing`——连摘要都未取得

`full_read` 与 `partial_read` 必附证据清单：`evidence_pages`（如 `["p3","p5"]`，核心档用章节号 `["§1","§4.2"]`）＋ `evidence_figs`（如 `["Fig. 1","Table 2"]`）。给不出证据链，不得申报这两个状态，降级并说明缺什么。

结论—锚点绑定：每个关键数值与结论后缀锚点，格式 `(p5)` `(Fig. 3b)` `(Table 2)`，同段连续结论可合并 `(p5–p6)`。页码与图号是硬事实：写作时想不起出处，回查原文补锚点；查不到则删掉该表述或改写为「原文提及但出处待核 ⚠️」。禁止凭印象补页码。

## 4 提取五件事

按读者理解顺序排列（先问题后细节）。缺任何一件，读者都无法理解或判断该文献：

| 提取项 | 内容 |
|---|---|
| 问题与方案 | 文章要解决的问题、该问题为什么难、解决它依赖的技术手段、文章的设计思路（通常对应总览图） |
| 装置与工艺 | 材料、结构、尺寸、关键参数，逐项给数值与单位 |
| 实验路线 | 有几条、每条的变量是什么、对照组怎么设 |
| 机理链 | 作者主张的反应路径或因果顺序，逐步标出 |
| 支撑证据 | 每条主张靠什么证据支撑，证据是直接还是间接 |

## 5 方法学审查

读 `references\审查清单.md`，按层逐项过。清单按通用统计、可复现性、物理意义、领域专属四层组织；领域专属层按子域路由，只过命中的子域，其余整节跳过并在交付中写出跳过范围。

审查不是找茬。命中项按三级归类，三级都要给出依据：

- **硬伤**——结论所依赖的前提不成立，引用该结论会出错
- **存疑**——数据不足以判定，作者未讨论或表述过强，需回查原始引用
- **缺失**——信息未报告，不等于未做；只说明不可复现，不推断作者行为

存疑项必须给出回查路径（追到哪篇文献的哪个表），否则降级为缺失。零命中时明写「未发现实质问题，已核对范围：<列出层与项与跳过子域>」，不以沉默充当通过。

## 6 标注纪律

区分三种来源，混同即为学术不诚实：

- **文中明确给出**——正文或表格中的数值，可直接引用
- **图中读取**——正文未列、从图上读到的数值，标 ⚠️ 并请用户对照原图
- **推断**——本方的判断，标为推断并给出推理依据

正文内部自相矛盾时，两处数值都列出并指明不一致，不替作者择一。数据与既有文献冲突时深挖机理，区分测量误差、方法学缺陷、模型假设和来源差异，不硬调和。

## 7 交付结构

```
read_status: full_read（中文含义见第 3 节）
证据清单：p3, p5–p6；Fig. 1, Fig. 3b, Table 2

主旨一句（这篇解决什么问题＋用什么手段＋核心结果数字）

一、这篇文章做了什么（先建图式，后铺细节）
  1.1 问题：文章要解决什么问题、为什么难（落到「没有它会怎样」，如结果不可重复／无法定量）
  1.2 手段：解决问题依赖的核心技术，各配一句「它是什么、为什么能打这个问题」
  1.3 方案：文章如何组合上述手段解决问题（设计逻辑，通常对应总览图）
二、装置与工艺（参数表）
三、实验路线与机理链
四、支撑证据核查
五、真实创新点（对比 prior art：别人做到哪、本文多走哪步；引文内无法对比时明说）
六、方法学审查（按硬伤／存疑／缺失分级；含零命中声明与跳过子域）
七、与用户自身研究的相关点
```

read_status 行随交付给出，四态中文含义见第 3 节；对用户口头转述时用中文含义，不念字段名。

第一章写作纪律（默认读者未读过原文、不熟悉文章子领域）：

- 术语首现即给一句人话解释，缩写先展开；不以子领域常识为免费前提。
- 问题段必须让读者感到痛：这个问题存在时会发生什么（测不准／测不到／不可重复）。
- 方案段讲清设计逻辑与对应证据位置（图号），为后续各章做索引。

第五节不是可选的：读完一篇却说不清它比既有工作多走了哪一步，等于没读。第六节审查结论与「是否引用」的建议分开写，用户可只取其一。

写第七节前先读宿主的用户信息文件（如 USER.md）中的课题条目取用户研究方向。该文件为空或无课题条目时，先问一句用户当前在做什么再动笔。用户未答或无从问起时，第七节改题为「通用切入点」，只写该文献的方法学范式在其领域交叉域内的可迁移点，并在该节开头声明未获用户课题信息。读完一篇文献却不回答「这对我有什么用」，等于把用户的检索成本转嫁回给他。

## 8 条目存档（用户明示需要存档时）

用户要求把精读结果存档备查时，落盘结构化精读条目。字段契约见 `references\精读条目字段契约.md`，骨架见 `references\template-reading.json`。

诚实定位（首次交付条目时用一句话告知用户）：本条目契约是无文献管理方案时的宽泛兜底，适合短期、小范围使用；散落的条目文件无检索、无去重、无版本管理，长期文献管理应使用专门方案（文献管理软件或专用文献库），届时把条目迁入。

落点：用户指定目录时以用户为准；未指定时落智能体数据目录的 `memory\reading-notes\<slug>.json`，跨会话持久。slug 取 DOI 尾段或「作者-年份-关键词」短横线小写形式，文件名与 slug 一致。

落盘后必须过校验，0 error 才算完成：

```
node scripts\validate-reading.mjs <条目.json>     （或 bun，见 §1.0 适配表）
```

跨会话续做：精读交付时同步写一份 `<slug>.draft.json`（`reviewed_at` 留空）；slug 未定时用 `draft-<doi尾段>.json`，定名后重命名。后续会话续做存档时从草稿转正：补 `reviewed_at` → 校验 0 error → 去掉 `.draft` 后缀落正式条目 → 删除草稿。禁止凭后续会话记忆重写已核实内容。

收尾一行汇报，说人话：读了哪篇、读到什么深度、条目存到哪个路径（＋报告路径，如成文）。不长篇复述流程，不出现内部字段名与档位代号。

## 9 多篇对比与综述成文

多篇横向对比：触发词是对比、比较、异同、这几篇哪个更可信。每一篇先各自走完第 1 至 7 节，再横向对齐。横向表固定五列：

| 指标 | 文献 A | 文献 B | 是否可比 | 冲突点 |

「是否可比」按测试条件、体系、仪器、指标定义逐列判，条件不同直接写不可比并说明差在哪一项。条件不可比时不比数值大小，改比方法学范式：控制变量哪一篇更严、统计口径哪一篇更保守、结论表述哪一篇更克制。冲突点写清各自依据，作者主张与本方审查结论分列。多篇的审查分级仍逐篇判，不合并成一句总评。

多篇成文综述：先从条目目录生成素材包，再写综述，最后校验引用。

```
node scripts\gen-review-material.mjs <reading-notes目录> -o <素材包.md>
node scripts\check-review-cites.mjs <综述.md> <素材包.md>
```

写综述时只准读素材包与按需重开的单个条目，每个论断后缀 `[slug]`，素材包里没有的数字禁止出现，前瞻判断显式标注「（综述者判断）」。引用校验 0 FAIL 才可交付。

## 10 不要做什么

- 不把「未报告」表述为「未做」。二者对作者的指控性质完全不同。
- 不堆砌缺陷充数。审查项无实质影响时，写「未发现实质问题」并给出已核对的范围。
- 不用权威口吻掩饰不确定。核对不到的事实写「待查」，不凭记忆补全。
- 不替用户决定是否采纳。对存在分歧的文献，给 A／B 两个引用策略与推荐项。
- 不在审查中混入本方偏好。方法学缺陷与个人口味分开写。
- 不以速览冒充精读，不凭印象补页码图号，不把素材包外的数字写进综述。
- 工具失败如实申报：同一会话第一次换替代方案，第二次停手请示，不硬试第三次。
