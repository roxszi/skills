# 出版商 PDF 补抓链路（通用流程）

> 全文供给的 PDF 版供应链：精读条目的 `pdf_path` 归档、需要 PDF 原版（版式 / 补充材料页码）时使用。HTML 正文提取走 `publisher-extract.md`，本档只管 PDF 文件本身。
> 链路顺序即优先级：**OA 直取 → 同域 fetch（无人值守首选）→ 原生下载（兜底）**。本档为该链路的本地正本。

## 第 0 步：探测与定性

1. Unpaywall 探测（`https://api.unpaywall.org/v2/{doi}?email=<邮箱>`，email 必填）：`is_oa: true` → 走第 1 步；`false` → 订阅内容，走第 2 步。
2. 红线：只拿 OA / 已订阅内容（机构登录态 / 校园网 IP 授权）；Sci-Hub 类第三方渠道默认关闭，仅用户显式授权才使用。

## 第 1 步：OA 直取（is_oa = true）

- Node（或 bun）fetch 脚本下载：`best_oa_location.url_for_pdf` → 流式写临时文件 → `%PDF` 魔数校验 → 原子改名落盘。OA 文献直链一般无拦截。

## 第 2 步：同域 fetch 链路（订阅内容，无人值守零弹窗首选）

适用：浏览器已能打开该出版商正文页（登录态 / IP 授权有效），但服务器外直链 fetch 被拦（Cloudflare 等，实测 10.1021 直链 403）。

1. 用宿主浏览器自动化能力打开文章 HTML 页并确认正文已加载（Cloudflare 挑战已过、clearance cookie 已建立）。
2. 在该 tab 用浏览器 JS 执行能力跑同域 fetch：`fetch(pdf直链, {credentials:"include"})` → blob 转 base64 → 返回。
3. base64 经宿主的大结果落盘能力写出 → 本地解码回 PDF → `%PDF` 魔数校验。
4. 特性：完全不经过浏览器下载管理器，不弹任何对话框，不受用户下载设置影响，文件直落目标目录——无人值守场景的标准路径。
5. ⚠️ 已知边界（2026-10-20 设计就绪、尚未实测）：响应体大（数 MB）时 base64 转换与落盘耗时增加；PDF 与正文不同域时会撞 CORS，改走第 3 步。

## 第 3 步：原生下载（兜底）

1. **执行前必须先发消息提醒用户**：「浏览器将弹下载确认框，请留意放行」。若用户浏览器开启了「下载前询问每个文件的保存位置」（安全考虑下的常见配置），无人值守时原生下载必然阻塞等待人工确认——此提醒不可省略，不可默认用户在盯屏幕。
2. 触发：浏览器自动化导航到 PDF 直链（真实浏览器过挑战后自动触发下载；自动化工具报 "Download is starting" 属**成功信号**，非错误）。
3. 落盘位置 = 浏览器默认下载目录；ACS 文件名 = DOI 斜杠换点（如 `acs.jcim.6c02860.pdf`）。
4. 归位：复制到 `<slug>/fulltext.pdf` + `%PDF` 魔数与 `%%EOF` 尾标记校验；同批重复副本（`(1)` `(2)` 后缀）列清单交用户确认清理，不擅删。

## 收尾校验（三步共用）

- 完整性：`%PDF-` 头魔数 + `%%EOF` 尾标记 + 体积合理（期刊论文数 MB 级）。
- 归档约定：落点由用户指定；未指定时落智能体数据目录 `memory\reading-notes\<slug>\fulltext.pdf`，条目内的 `doi` 与本路径互相可查。
- 失败如实申报：三步全失败 → 摘要级继续后续流程 + 条目标 ⚠️ 待补 PDF，不阻塞精读主线（HTML 全文可读时）。
