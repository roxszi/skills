# 精读条目字段契约

> 用途：落盘结构化精读条目时逐字段填写。校验者：`scripts\validate-reading.mjs`（node ≥ 20 或 bun 执行，见 SKILL.md §1.0 适配表），0 error 才算完成。
> 骨架文件：`references\template-reading.json`。校验契约与本文件须双向同步，改一处即改另一处。
> 领域扩展契约：本字段集按化学／光谱领域定制（`spec_evidence_zh` 谱学证据、`validation_zh` 方法学验证等）。其他领域复用本技能时，可按同一契约模式增删字段，须与校验脚本的 REQUIRED／LIMITS 定义双向同步，并跑 `tests\run-tests.mjs` 回归。

## 字段表

| 字段 | 必填 | 上限（字符） | 内容 |
|---|---|---|---|
| `slug` | ✅ | — | 与文件名一致；取 DOI 尾段或「作者-年份-关键词」短横线小写 |
| `title_en` | ✅ | — | 原始题名 |
| `title_zh` | ✅ | — | 中文题名 |
| `journal` | ✅ | — | 期刊名 |
| `year` | ✅ | — | 整数，1900–2100 |
| `doi` | — | — | 有则填 |
| `read_status` | ✅ | — | 四态枚举：`full_read` / `partial_read` / `abstract_only` / `missing` |
| `evidence_pages` | full_read、partial_read 时 ✅ | — | 数组，如 `["p3","p5"]`；无页码版用章节号 `["§1","§4.2"]` |
| `evidence_figs` | full_read、partial_read 时 ✅ | — | 数组，如 `["Fig. 1","Fig. 3b","Table 2"]` |
| `background_zh` | ✅ | 300 | 背景与动机：领域痛点、为何做这项工作 |
| `question_zh` | ✅ | 200 | 核心科学问题：本文要回答什么 |
| `system_zh` | ✅ | 200 | 化学体系：分析物／基质／基底／材料 |
| `method_zh` | ✅ | 600 | 方法与关键参数：机制细节不只罗列名词；仪器、条件、参数给全 |
| `spec_evidence_zh` | ✅ | 400 | 谱学／数据证据：特征峰位与归属、特征数据，带锚点 |
| `results_zh` | ✅ | 600 | 主要结果：带数值与锚点 |
| `performance_zh` | — | 300 | 性能摘要：LOD、线性范围、回收率等概述 |
| `performance_metrics` | — | ≤5 条 | 键值对数组 `{"label":"LOD","value":"0.8 nM"}`，label 与 value 不得为空 |
| `validation_zh` | — | 200 | 方法学验证状态：ICH Q2 六参数做了哪几个、缺哪几个 |
| `innovation_zh` | ✅ | 300 | 真实创新点：对比 prior art，别人做到哪、本文多走哪一步 |
| `limitation_zh` | ✅ | 300 | 局限与风险：作者自认的与本方看出的分开表述 |
| `insight_zh` | ✅ | 300 | 对本方课题的启示；无关联则明说无关联 |
| `tags` | ✅ | 3–8 个 | 方法／体系标签，如 `["EC-SERS","AgNPs","PLS"]` |
| `key_figure` | — | — | 最关键一张图，如 `"Scheme 1"` |
| `reviewed_at` | ✅ | — | 精读日期 `YYYY-MM-DD`；草稿态留空 |

## 校验规则

- **error（拦截交付）**：缺必填字段；`read_status` 不在四态内；`full_read`／`partial_read` 缺 `evidence_pages` 或 `evidence_figs`；`year` 非 1900–2100 整数；`tags` 数量越界或含空元素；`performance_metrics` 非数组或元素缺 label／value。
- **warning（逐条人工判断）**：内容字段超长；`reviewed_at` 非 `YYYY-MM-DD`；`performance_metrics` 超过 5 条；`slug` 与文件名不一致。

超长字段按「先删水话再落盘」处理，不改上限迁就内容。

`references\template-reading.json` 是骨架样例，文件名与样例 slug 不一致，校验它时出现的 slug 一致性 warning 属预期；正式条目一律以 slug 命名文件。

## 执行方式

```
node scripts\validate-reading.mjs <条目.json>          # 逐条打印 error 与 warning（或 bun）
node scripts\validate-reading.mjs <条目.json> --quiet  # 单行结果，供流程内调用
```

退出码：0 = 无 error；1 = 有 error（回改后重跑）；2 = 用法错误。校验器只读文件，不修改条目。

## 素材包与引用校验

```
bun scripts\gen-review-material.mjs <reading-notes目录> -o <素材包.md>
bun scripts\check-review-cites.mjs <综述.md> <素材包.md>
```

素材包由条目生成，带 `[slug]` 锚点，是综述引用合法集的唯一来源。带 error 的条目不进素材包；warning 条目进包并在包内标注复核提醒。引用校验剔除 markdown 链接、行内代码与围栏代码块后再匹配 `[slug]`，有非法引用则 FAIL。
