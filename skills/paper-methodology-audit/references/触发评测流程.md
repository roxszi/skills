# 技能触发评测流程

> 用途：评�� `paper-methodology-audit` 的 frontmatter description 是否把用户请求正确路由到本技能。
> 评测器：`scripts\run_eval.mjs`（node ≥ 20 或 bun 执行，见 SKILL.md §1.0 适配表）。评测集：`tests\eval-queries.json`。评测结果归档在 `tests\eval-runs\`（答案 JSON 与报告分开存放）。

## 为什么自建

`skill-creator\scripts\run_eval.py` 依赖 `.claude\` 项目根与 claude CLI，通用性差。改用宿主的子会话能力做模型探针（能力定义见 SKILL.md §1.0 适配表；EasyClaw 为 sessions_spawn，Cherry 为 session_create／session_read）：子会话与主会话挂载同一份技能清单，其路由判断就是真实运行时行为。

## 两层检查

| 层 | 命令 | 作用 | 是否需要模型 |
|---|---|---|---|
| 离线覆盖 | `node scripts\run_eval.mjs --lexical` | 正例触发词是否写进 description；负例是否需要显式排除句 | 否 |
| 模型路由 | `node scripts\run_eval.mjs --answers <answers.json> --report <out.md>` | 真实模型对每条请求选哪个技能，算混淆矩阵与 F1 | 是 |

阈值：召回率 ≥ 90%，精确率 ≥ 80%，且无缺答案项。

## 模型探针的完整步骤

1. **环境自检（必做一次）**：确认被测子会话的运行环境挂着同一份技能清单。命令 `node scripts\run_eval.mjs --canary --emit-prompts <canary.txt>` 生成自检提示，发给一个子会话，期望回答里的 `mounted_skill_names` 包含 `paper-methodology-audit` 且 `sees_block` 为 true。自检不过则后续结果不可信。

2. **生成探针模板**：

```
node scripts\run_eval.mjs --queries tests\eval-queries.json --emit-template <out.txt>
```

模板内请求部分为占位符 `__UTTERANCE__`，同目录另出 `<out>.map.json`（id → 请求原文、标签、期望技能）。

3. **投递**：每条请求一个子会话，用宿主子会话投递能力传模板替换占位符后的文本，标题统一为 `eval<轮次>-<id>`。一轮 24 条一次性并发投递。

4. **收集**：子会话的最终回答优先经宿主的会话读取／投递通道回收，避免逐会话轮询；具体通道按宿主能力（§1.0 适配表）确定。

5. **打分**：

```
node scripts\run_eval.mjs --queries tests\eval-queries.json --answers <answers.json> --report <report.md>
```

`answers.json` 形如 `{"P01": {"load": true, "best_skill": "paper-methodology-audit", "reason": "..."}}`。

答案与报告归档到 `tests\eval-runs\`，文件名带日期与轮次（如 `eval-answers-2026-10-20-run1.json`）。

## 评测集写法

每条含：`id`、`label`（positive／negative）、`utterance`（用户请求原文）、`expect.skill`（期望归属，`none` 表示不加载任何技能）、`alt_skill`（可接受的替代归属，仅负例）、`expect_any`（description 中应出现的触发词之一，供 `--lexical` 用）。

正例须覆盖触发语族：路径型、动作型（精读／讲一讲／看一下）、判断型（靠谱吗／有没有硬伤）、目的型（能不能支撑方案）、复数型（对比几篇）、素材受限型（只有 DOI）、格式型（docx）、速览型（快速看一眼）。
负例须覆盖：同领域但不涉具体文献的知识问答、实验方案设计、数据建模、语言润色、格式转换、文献检索、开题报告审阅、仪器故障、绘图、方向性综述（可用 `alt_skill` 接受 `tech-brief-writer`）。

## 已知边界

- 模型探针耗时长且跨会话工具在无人值守时需人工批准，一轮 24 条须一次性并发投递并靠投递通道回收答案。
- 子会话的技能清单由宿主挂载，主会话新增或删除技能后须重跑自检。
- 路由判断受当日模型版本影响，评测报告须记日期；换模型后重跑。
- 评测集只覆盖 `paper-methodology-audit` 的路由；与其他技能的边界（如 `tech-brief-writer`）靠负例的 `alt_skill` 记录，不构成对其他技能的评测。
