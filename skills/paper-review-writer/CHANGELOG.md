## 0.4.1（2026-10-23）

- **精读→成文自动续跑**（用户建议：停点确认内容空洞——回收后一般只是回「继续」，白等；且批量精读纯本地作业，适合夜间无人值守挂机，次日直接看综述初稿）：回收完成 → validate → brief → 0 error 即直接进第 5 节，不设人工停点；有 error 回改后同样自动续跑。停点仅剩两类天然卡点：error 修不动、补拉循环触发需人守渠道（§5.2 原规则不变，触发即停等用户）。前提已核实：精读全链路只读 digests/ + papers_txt/ 本地落盘文件，零 URL 访问。纯 SKILL.md 条款，代码不动。

- 回归 39 → 53 断言（map 7：多作者 et al. / 未获取跳过 / 单作者 / verified 缺失抛错 / 空清单抛错 / summaries 为空抛错 / 全 missing 空章 exitCode 1；dispatch 6：任务卡要素 / 回收队列 / digest 缺失 ⚠ / 待修分类 / batch 回落 / 清单缺失与空数组抛错）。

## 0.3.0（2026-10-23）

- 首次双实战（59 篇细胞拉曼综述全流程 + 用户五点复盘）驱动的改造。
- **check 缺省名 bug 修复**（实战踩中）：check 缺省找「调研综述.md」而 assemble 缺省输出「综述.md」，自定义 `--out` 后跑 check 必假 FAIL。改为两处同名（综述.md）+ 旧项目唯一候选自动顶上 + 多候选拒绝并指引；回归 36 → 39 断言（缺省名命中 / 唯一候选回退 / 多候选拒绝）。
- **预调研交互纪律**（用户反馈①：十几分钟静默被误判假死）：开跑前申报预计时长；检索并行 ≤3，单源限流即切备源不空等。
- **检索全库覆盖红线**（用户反馈③：候选偏 OA 浪费机构订阅）：候选清单不以「能否拿到全文」筛选，OA 倾斜只允许发生在获取端；停点 1 增加获取环境（校园网/机构网）与渠道授权问询。
- **获取停点原因分类**（用户反馈②②b）：未获取篇目逐类给原因与下一步建议，「只是被验证码挡住」显式说，让用户用几分钟放行验证码替代机械手工下载；playbook 新增分类表与下载按钮场景动作。
- **并发策略写死**（用户反馈④：套餐限并发 + 5 小时 token 限额被打爆）：标准档默认同时 2 个子会话，完成事件驱动排队补派；停点 2 问档位（标准 / 加速自定）；批量派发前任务卡清单落盘台账。
- **任务卡 stdin 编码条款**（实战 silent bug：PS 管道默认编码把中文静默替换为 ?，校验通过但中文全毁）：中文必须经执行工具 stdin 直传，管道场景须先设 UTF-8 且落盘后统计 ? 数验证；适配表新增该能力行。
- **写作防漂移条款**（实战 silent bug：上标 ⁵ 被静默写成「的 5 次方」）：含上标 Unicode/带圈数字的章节落盘后抽查。
- 文献映射章写死脚本生成（authors 分号分隔取首作者），禁正则二次补丁。
- 深度二次评估预算可在停点 2 与用户确认放宽，如实申报优先于预算（实战 59 篇短文清单超支 50.8% 的复盘）。

## 0.2.2（2026-10-22）

- check 子命令扩展为「引用校验 + 交付自检」，0.2.1 遗留的 3 号项落地。新增三项自检：
  - 章节齐全性（FAIL 级）：内置 9 章关键词表匹配综述一至三级标题（标题先剥编号前缀），缺章逐条列出；一至三级标题切块后同一扫描供三项自检复用，子标题内容归入父章。
  - 文献映射一致性（FAIL 级）：文末映射节（「文献映射」或「参考文献」标题）的行首编号必须覆盖素材包全部编号；映射节缺失时不双报（章节齐全性已覆盖），映射节内素材包外编号由既有 invalid 全文校验覆盖。
  - 「（综述者判断）」标注存在性（WARN 级）：现有局限与未来方向两章缺失标注仅警告，不拦交付、不影响退出码。
- 新增豁免通道：project.json 的 `report.optional_sections`（章名数组）把用户合法裁剪的章从必查表剔除；示例模板与 loadProject 缺省值同步。
- `review_check.json` 新增 `sections_missing`／`mapping_missing`／`judgment_warnings` 三字段；`ok` 收紧为「引用合法且被引非空且章节齐且映射齐」；全部通过时打印一行自检汇总（章节 x/x、文献映射 x/x、判断标注 x/x）。
- 回归 30 → 36 断言（新增交付自检 6：完整合规 / 缺章 / 映射缺编号 / 判断标注缺失仅警告 + 纯 WARN 零退出码 / optional_sections 豁免；原「全合法引用通过」用例 fixture 升级为完整合规综述，断言不变）。
