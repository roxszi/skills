## 二、四点反馈逐条复盘

### 1. 预调研独立化——采纳，补「深度上限」

走偏实锤：候选清单迭代时为写「一句话定位」读摘要，预调研做成了半篇综述。skill §2 已有「候选生成后交用户确认」但缺深度约束。

v0.2 改法：预调研只到题录层（title/DOI/年/期刊/分组，题名+通识粗判分组）；方向、规模、分组经用户确认后清单**冻结**；一句话定位下沉到 digest 阶段自然产生。冻结前不 download、不派读（与既有红线一致）。

### 2. url 与 pdf 的取舍——混合策略：url 读内容，pdf 存档

实战证据支持用户判断：HTML walk 提取的文本质量显著优于 pdfjs（HTML 里公式、图题、表格是结构化的；pdfjs 双栏串行、公式乱码）。但 url 一次性（页面改版即失），pdf 是可复查资产。

v0.2 获取顺序（每篇）：
1. HTML 全文可达（OA/订阅放行）→ walk 提取文本入库（阅读正本）+ 顺手存 pdf 直链副本（存档资产）
2. HTML 被拦 → DOI 直跳浏览器降级（tab 预检→`doi.org/{doi}`→静置→walk 提取→output-file 落盘）
3. 仅 pdf 可得 → pdfjs 提取
4. 提取为空（扫描版）→ OCR 分支，提示用户
5. 全链失败 → 标「仅摘要/未获取」进停点问询

浏览器降级链沉淀为 references/playbook（能力语言，宿主适配表已含浏览器能力行）。

### 3. 子会话分工与交付物层次

两类子会话性质不同，skill 须分开写：
- **搬运工**（全文获取）：涉网、有反爬风险 → 串行或 1~2 并发，1 个子会话打包执行。交付 = 获取台账（每篇：状态/全文路径/渠道/失败原因/pdf 副本路径），**不做任何解读**（无综述框架，解读即污染）。
- **科学家**（逐篇摘要）：读本地文件、无拦截风险 → 2~3 篇/组小并发。交付 = 结构化摘要条目，任务卡须带综述核心问题（带着问题读）。

用户问「交付爬取结果还是吃透总结」：两层都要，不能互相替代——搬运工的输出是可复用资产（papers_txt + 台账），科学家的输出才是综述直接输入。砍掉任何一层都会把成本压回主会话。

### 4. 停点问询——采纳为强制节点

这次 v1 是「先斩后奏」（自决定用 45+21 出 v1），未先问。v0.2 把获取完成设为强制停点：报告台账（几篇全文、几篇失败、原因分类）→ 问用户「A. 等补全再综述（慢，只写一遍）；B. 先用已到手综述一版、缺口标注、补到后增量更新（快，但综述更新≈局部重写）」。代价说清，用户拍板。

### 5. 上下文爆炸与分会话——「状态外化」优于「固定分会话」

爆炸主因排序：补抓执行在主会话（最大头，应下沉搬运工子会话）> 综述两次全篇重写（章节文件化可解）> 预调研过深（第 1 条可解）。

用户提议的双会话方案（会话 1 立项+搬运，会话 2 科学家）可行，但额外收益有限：科学家会话开头必须重读台账/清单/素材包，恢复成本省不掉；且真正的杀手（抓取执行）用「搬运工下沉子会话」就能解决，主会话无需拆两次。

v0.2 取向：**不强制分会话，把「知识状态」全部外化到磁盘**（papers_meta、台账、summaries、digest/brief、章节文件），关键节点强制停点报告。任意时刻会话可弃可续——新会话读磁盘状态即可恢复，上下文爆炸只损失当前轮，不损失项目。若用户偏好双会话形态，同一套接口天然支持，作为推荐形态写入而非硬性规定。

### 6. sci-hub 与付费墙策略（须用户拍板）

未主动走的直接原因：skill v0.1.2 自带红线（§2/§6：第三方转载渠道默认关闭，仅用户显式授权才开启，授权一次只对本项目生效），此边界来自版权合规（Sci-Hub 类渠道在多司法辖区被裁定侵权）。这是默认关闭、拍板可开的设计，不是能力缺失。

v0.2 交互改造：付费墙卡住达阈值（建议 ≥2 篇或单篇阻塞关键章节）时，停点问询给出三选项：①用户自下载（最干净，本次 54 号即此模式）；②合法文献传递（馆际互借/向通讯作者索取）；③显式授权第三方渠道（授权记录进台账）。单篇小缺口不打扰用户，标缺口继续。

## 三、skill 设计与实战的偏差清单（v0.2 必改）

1. **PDF 中心 → HTML 优先**：现 §3 整节按「下载 pdf→extract」设计，实战主路线是浏览器 HTML walk；download 命令的候选链对反爬出版商（Cloudflare/Imperva/机构挡板）基本失效，实战全程绕过。获取节重写为混合策略，浏览器降级链入正文 + playbook。
2. **validate 口径冲突**：校验器要 full_read/partial_read/abstract_only，实战项目用 L1/L2（与宿主精读技能、papers 库对齐）。二选一统一，契约↔脚本↔SKILL.md 三处同步。
3. **缺强制停点**：清单冻结、获取完成两处停点入 §0/§3。
4. **缺增量更新**：综述按章节文件产出 + 拼装，支持补拉循环（上限建议 v1 初稿→v2 补全→v3 终稿，超限重开项目）。
5. **摘要模板与实战任务书脱节**：init-summaries 模板未含 L1/L2 深度字段与综述问题注入位。
6. **台账文件缺失**：results.json 只记录下载结果，不覆盖 HTML 渠道与人工干预记录，需升级为获取台账。
