# 条目 → 演示文稿桥接配方（PPT）

> 场景：综述交付后需要汇报用幻灯片。本技能不产 PPT——这是设计取舍（宿主的演示文稿生成能力已覆盖，技能内重建即与宿主能力重复）；本文只给取数映射与文案骨架，把流水线产物接给宿主能力。数字唯一合法来源与综述相同 = `review-material.md`。

## 取数映射（流水线产物 → 幻灯片素材）

| PPT 素材 | 来源文件与字段 | 约束 |
|---|---|---|
| 篇名 | `summaries/summary_{id}.json` 的 `title_zh`（缺则 `title_en`） | 原文照抄，不缩写改写 |
| 分组归属 | `papers_meta.json`（或 verified）的 `kind_zh` | 与综述章节分组一致 |
| 一句话问题 | summary 的 `question_zh` | 裁到 ≤40 字 |
| 方法路线 | summary 的 `method_zh` | 裁到 ≤80 字 |
| 关键数据点 | summary 的 `performance_metrics[].label` + `value` | 每篇 ≤3 条，每条带 `[编号]` |
| 谱学证据（化学/光谱领域条目可选） | summary 的 `spec_evidence_zh` | 可替换「关键数据点」行的取数来源 |
| 一句话启示 | summary 的 `innovation_zh` 或 `results_zh` | 超出素材包字面的归纳标「（综述者判断）」 |
| 深度标注 | summary 的 `read_status` 中文含义 | 「未获取」条目不进数据页 |

## 每篇 2 页文案骨架

- **页 1「做了什么」**：篇名 + 分组 + 问题一句 + 方法一句。
- **页 2「结果与启示」**：关键数据点 ≤3 条（每条带 `[编号]`）+ 对综述核心问题的一句启示。

开篇总览页与结尾结论页由全库层取数：开篇 = 各分组篇数与代表文献；结论 = 综述「未来方向」章要点压缩（同源改写，不新增数字）。

## 交付方式

把上表与骨架写成一张任务卡，交给宿主的演示文稿生成能力（版式、模板、配色按宿主能力约定）；生成后抽查数字与素材包一致——PPT 与综述同一红线：素材包里没有的数字禁止出现。

## 备选路径

若宿主另有独立的文献调研 PPT 生成工具（本技能的上游同源工具即属此类），可用其对同一批文献单独起项目；两套条目 schema 不互通，禁止混用同一项目目录。
