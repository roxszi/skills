# 条目字段契约（summaries/summary_\<id\>.json）

> 用途：精读落盘条目时逐字段填写。校验者：`review.mjs validate`（node ≥ 22.13 或 bun，见 SKILL.md 宿主适配表），0 error 才算完成；`review.mjs save` 落盘时同步校验。
> 骨架样例：`templates/summary.example.json`。本文件与 `scripts/schema.mjs`、SKILL.md 三处双向同步，改一处即改三处。
> 领域扩展契约：`system_zh`／`spec_evidence_zh`／`performance_metrics`／`validation_zh` 四个字段按化学／光谱领域定制（体系、谱学证据、定量性能、方法学验证），其他领域复用时按同一模式增删字段，须与 `schema.mjs` 的 REQUIRED/LIMITS 双向同步并跑 `tests/run-tests.mjs` 回归。

## 字段表

| 字段 | 必填 | 上限（字符） | 内容 |
|---|---|---|---|
| `id` | ✅ | — | 与 papers_meta.json 一致的编号（save 子命令自动回填） |
| `title_en` | ✅ | — | 原始题名 |
| `title_zh` | ✅ | — | 中文题名 |
| `journal` | ✅ | — | 期刊名（verify 后自动回填） |
| `year` | ✅ | — | 整数，1900–2100 |
| `doi` | — | — | 有则填 |
| `read_status` | ✅ | — | 四态枚举：`full_read`（全文已读）/ `partial_read`（部分精读）/ `abstract_only`（仅摘要）/ `missing`（未获取）。禁止以仅摘要冒充全文已读 |
| `evidence_pages` | full_read、partial_read 时 ✅ | — | 数组，如 `["p3","p5"]`；无页码源（EPMC XML）用章节号 `["§1","§4.2"]` |
| `evidence_figs` | full_read、partial_read 时 ✅ | — | 数组，如 `["Fig. 1","Fig. 3b","Table 2"]`；图题索引（digest 尾部）可辅助定位 |
| `background_zh` | ✅ | 300 | 背景与动机：领域痛点、为何做这项工作 |
| `question_zh` | ✅ | 200 | 核心问题：本文要回答什么 |
| `method_zh` | ✅ | 600 | 方法与关键参数：仪器、条件、参数给全，不只罗列名词 |
| `results_zh` | ✅ | 600 | 主要结果：带数值与锚点（如 `(p5)`） |
| `innovation_zh` | ✅ | 300 | 真实创新点：对比 prior art，别人做到哪、本文多走哪一步 |
| `limitation_zh` | ✅ | 300 | 局限与风险：作者自认的与本方看出的分开表述 |
| `tags` | ✅ | 3–8 个 | 方法／体系标签，如 `["EC-SERS","AgNPs","PLS"]` |
| `reviewed_at` | ✅ | — | 精读日期 `YYYY-MM-DD` |
| `system_zh` | 领域扩展 | 200 | 体系：分析物／基质／基底／材料 |
| `spec_evidence_zh` | 领域扩展 | 400 | 谱学／数据证据：特征峰位与归属、特征数据，带锚点 |
| `performance_metrics` | 领域扩展 | ≤5 条 | 键值对数组 `{"label":"LOD","value":"0.8 nM"}`，label 与 value 不得为空 |
| `validation_zh` | 领域扩展 | 200 | 方法学验证状态：验证参数做了哪几个、缺哪几个 |
| `key_figure` | — | — | 最关键一张图，如 `"Scheme 1"` |
| `notes` | — | — | 自由备注 |

## 校验规则

- **error（拦截交付与素材包）**：缺必填字段；`read_status` 不在四态内；`full_read`／`partial_read` 缺 `evidence_pages` 或 `evidence_figs`；`year` 非整数或越界（1900–2100）；`performance_metrics` 非数组或元素缺 label／value。
- **warning（进素材包但标注复核提醒，逐条人工判断）**：内容字段超长；`tags` 数量越界（3–8）或含空元素；`performance_metrics` 超过 5 条；`reviewed_at` 非 `YYYY-MM-DD` 格式。

超长字段按「先删水话再落盘」处理，不改上限迁就内容。

## 阅读深度与证据链的对应关系

| read_status | 中文含义 | 证据链要求 |
|---|---|---|
| `full_read` | 全文已读 | evidence_pages + evidence_figs 必填 |
| `partial_read` | 部分精读 | 必填，且综述转述范围不得超出已读章节 |
| `abstract_only` | 仅摘要 | 无证据链要求；综述中只可转述摘要级信息 |
| `missing` | 未获取 | 不得在综述正文中引用其任何内容细节 |

## 执行方式

```
node scripts/review.mjs validate --project <项目目录>              # 全量校验
node scripts/review.mjs validate --project <项目目录> --id 01      # 单篇校验
node scripts/review.mjs save --project <项目目录> --id 01          # stdin JSON 边落盘边校验
```

退出码：0 = 无 error；1 = 有 error；2 = 用法错误。校验器只读文件，不修改条目（save 除外）。
