# 批量文献调研与综述成文

## 这个技能解决什么

调研综述的常见失效有五种：引用题录张冠李戴、把摘要当全文读、综述里的数字无出处、主会话直接吞全文导致上下文爆炸、以及综述写完后补文献被迫全篇重写。本技能用一条脚本流水线把「取原文」与「读原文」分离：脚本负责核验、获取、提取与压缩，智能体只读消化后的缓冲；每篇条目带证据链，综述只准引用素材包内的内容并经编号校验闭环。项目状态全部落在磁盘文件，会话可弃可续，补文献只重写涉及章节。

分工边界：单篇深读与逐篇方法学审查属宿主精读类技能的职责；本技能管主题驱动的批量调研项目。两类技能的条目字段命名对齐，深读产物可并轨使用。

## 0 规模、预调研与停点

| 档位 | 适用 | 路径 |
|---|---|---|
| 简化路径 | 少于 6 篇，或用户只要速览式梳理 | 不建完整项目：直接按 §3 取原文，仍优先按 §4 任务卡派子会话逐篇读并落条目（无子会话能力才主会话逐篇），再走 §5 成文 |
| 全流水线（默认） | 6 篇及以上，或用户明确要完整调研 | 按第 2–5 节完整走 |

启动前向用户完整告知五步工作流与 tips（一次性说完，再开跑预调研）：

1. **第 1 步·预调研海选**：全库检索候选文献，需等十几分钟量级（期间静默属正常，完成即汇报命中数），返回海量题录（标题/年份/期刊/分组）后与用户一起敲定调研方向与清单范围。
2. **第 2 步·获取全文**：逐篇拉取全文，教育网/校园网环境成功率最高；拉取一轮后交台账，未获取的逐类说明原因，等用户定夺（放行验证码 / 换渠道 / 先用已有文献写）。
3. **第 3 步·吃透文献**：先跑图表提取（§3.4），再批量精读全部到手文献，纯本地低并发作业，耗时数小时，适合夜间挂机；进展顺利则**自动连跑第 4 步**，只有卡点才停（条目回改修不动 / 补拉需人守浏览器）。
4. **第 4 步·成文与自检**：按章节写综述（配图用 figures/ 相对路径）+ 交付自检，完成后直接看初稿。
5. **第 5 步·一键自包含 HTML 导出**：综述 md 转单文件 HTML（图片内嵌、零外链、离线可开）。本步独立可重入：用户之后说「重新导出 HTML」「重新执行第五步」「我修正了图片，请重新导出」，只重跑本步，不回跑精读与成文。

随告知一并申报量化预期：论文篇数、走的档位、预期产物（条目数 + 综述一篇 + 自包含 HTML 一份）、可能拿不到全文的比例、全流程总时长量级（文献多时可能跨一天一夜）。告知后即开预调研；候选清单经用户确认后才获取、不派读。

**预调研纪律**：候选调研只到题录层（标题/DOI/年份/期刊/分组），分组按标题与领域通识粗判，不为写定位语去读摘要——深度评估是 §4 条目阶段的事。清单经用户确认方向、规模、分组后即**冻结**，此后不再扩池（增补走 §5.2 补拉循环）。

**预调研交互纪律**：检索开跑前向用户申报一句「检索预计时长 + 期间静默、完成后汇报命中数」——预计超过 5 分钟的静默必须预告，不让用户误判假死。检索查询并行 ≤3，单源限流（429 类）即切备源，不对单源空等重试。检索要求全库覆盖（OA 与订阅文献都在题录层命中），**不以「能否拿到全文」筛选候选**——可获取性由 §3.2 机构直链与渠道四档在获取阶段解决，检索层向 OA 倾斜会系统性漏掉订阅文献、浪费机构订阅资源。

**两处强制停点**（到点必须报告并等用户拍板，不自作主张）：

1. 清单冻结停点：候选清单交用户确认，并一并问两件事——获取环境（是否在校园网/机构网络内，决定订阅文献直链成功率，高校用户默认是）与渠道授权（是否把已知合规渠道写入白名单）。
2. 获取完成停点：交获取台账（几篇全文在手、几篇仅摘要、几篇未获取），未获取篇目必须**逐类给原因与下一步建议**：验证码/挑战页拦截（理论上可获取，重试即可，可请用户适时关注浏览器协助放行）、机构未订阅（硬缺口，走渠道四档或用户手下载）、IP 拦截、DOI 失效（元数据错，可修正重试）、扫描版。「只是被验证码挡住」要显式说——这决定用户能否用几分钟放行验证码就补齐全部缺口，避免用户误以为只能做机械手工下载。台账交待后问用户三件事：A. 等补全再综述（慢，综述只写一遍）；B. 先用已到手文献综述一版、缺口标注、补到后增量更新（快，但需增量更新）；C. 精读并发档位——标准档（默认，同时 2 个子会话，模型用量平缓，适合限并发/按量套餐）或加速档（用户指定并发数）。拍板前不进 §4。

**会话接续**：项目状态全部在磁盘（清单、台账、条目、章节文件）。任意会话中断后，新会话按顺序读清单 → 获取台账 → digests/brief.md → 已写章节文件即可恢复现场，不依赖原会话记忆。

对用户交互一律用中文含义（全文已读／部分精读／仅摘要／未获取），不念枚举值与字段名。

## 2 项目初始化与论文清单

```
node scripts/review.mjs init --project <项目目录>
```

生成固定骨架：`papers_meta.json`（论文清单，输入）、`project.json`（可选配置）、`papers/`、`papers_txt/`、`digests/`、`summaries/`、`deliverables/sections/`。

清单 `papers_meta.json` 格式见 `templates/papers_meta.example.json`：每篇至少 `id` 与 `title`，`doi`／`pmcid`／`pmid` 能给则给（核验与获取成功率显著提高）；`kind`／`kind_zh` 是综述分组的分类键，按主题自定；`read_depth` 是预判读法（brief＝只读摘要／targeted＝digest+定向回查／full＝通读全文），依据标题与摘要同综述问题的关联度粗判，供 §4 条目阶段二次评估用。`id` 用两位编号（01、02…），综述引用就是它。

清单来源三种：用户直接给、检索能力生成候选后交用户确认（预调研只到题录层，见 §0）、宿主文献库导出。清单确认即冻结。

`project.json` 的 `apis.mailto` 必须配真实邮箱（公共 API 礼貌要求，假邮箱会被 Unpaywall 拒绝）。`compliance` 节管获取渠道授权，渠道分四档：

- **①用户自下载**：用户提供文件，最干净，小缺口首选。
- **②合法文献传递**：馆际互借／向通讯作者索取；发起后标「在途」不阻塞，回件补入。
- **③知名权威第三方白名单**：`compliance.tier3_allowlist` 数组，条目为渠道名。**项目所有者显式写入即视为持久授权**，获取阶段命中即自动执行，无需逐次问询；台账记渠道与授权依据。示例见模板注释。
- **④其他第三方渠道**：默认关闭；`allow_third_party` 保持 false，仅用户对具体渠道逐次显式授权后才开启，授权记录进台账。

## 3 流水线前半程（获取阶段）

按顺序执行，任何一步失败先看单行错误，修输入再重跑；`download`／`extract`／`digest` 支持 `--id <编号>` 单篇重试，不整批重跑。

### 3.1 元数据核验

```
node scripts/review.mjs verify --project <项目目录>
```

四源链 Crossref → OpenAlex → Europe PMC → Unpaywall 逐篇核验：题录回填（清单已有值优先，缺才补）、无 DOI 的按题名精确补查、OA 链接发现、**英文摘要回填**（EPMC/Crossref 响应顺带提取，供仅摘要条目转述与 init-summaries 写入）。产物 `papers_meta.verified.json`。逐条检查核验结果：题录与用户意图不符（同名异文、年份对不上）当场修正清单再核验，不带病往下走。

### 3.2 混合获取（url 读内容，pdf 存档）

阅读正本 = 全文文本（`papers_txt/{id}.txt`）；pdf 是存档资产（凡出版商提供合法直链就顺手存 `papers/{id}_{slug}.pdf`），日后复查数值与深读不再抓。每篇按序尝试：

1. **HTML 直达**：OA 或订阅放行的全文页 → 页面内提取脚本取正文文本入 `papers_txt/`（HTML 语义标记比 pdf 排版提取干净，公式、图题、表格结构保留更好），并顺手存 pdf 直链副本。
2. **浏览器降级**：直链被反爬拦截（验证码/挑战页/机构挡板）或落点页只有「PDF 下载」按钮而无直接链接 → 按 `references/acquisition-playbook.md` 走浏览器路线：先查已开标签页，再 DOI 跳转（`https://doi.org/{doi}`）→ 静置 → 页面内提取（或定位 `citation_pdf_url` / 下载按钮）→ 结果落盘。涉网获取一律串行或 ≤2 并发，多线程易触发拦截升级。验证码类拦截属人工协助项：保留现场请用户放行后重试一次，不自动绕过、不连坐重试。
3. **仅 pdf 可得**：下载 pdf + §3.3 提取。
4. **扫描版**：提取文本近乎为空 → 判定扫描版，走宿主 OCR 或标「未获取」。
5. **全链失败** → 按 §2 渠道四档依序处理：①请用户提供文件；②发起文献传递标「在途」；③白名单命中自动下载；④逐次问询授权。仍无全文标「仅摘要／未获取」，台账留档。

### 3.3 提取与精读缓冲

```
node scripts/review.mjs extract --project <项目目录>
node scripts/review.mjs digest --project <项目目录>
```

extract：pdf 逐页提取为 `papers_txt/{id}.txt`（带 `===PAGE n===` 标记供定向回查）；同号文本文件已存在的跳过（HTML 路线已产出）；无文本且有 PMCID 的自动降级为 EPMC XML 全文（无页码，条目证据链改用章节号）；扫描版报错并标注。

digest：每篇压缩为 ≤2.6KB 缓冲 `digests/{id}.md`（首页 + 关键节 + 图题索引）。图题索引给出 Fig./Scheme/Table 首现页码；同目录另落 `digests/{id}.figs.md`（每个图题首现处向后 400 字符的原文上下文，≤10 图；caption 大多紧邻首现处，读上下文即知图意，无需渲染位图）。需要看真图时按页码用宿主 pdf 阅读能力读那一页，不整本读。

全库另拼 `digests/keyfacts.md`（每篇 ≤1200 字符：首页摘要 + method/results/discussion 片段）——精读前的全库一览，定位为**按需查段，不整读**：主会话写任务卡、裁决二次评估升级申报时查段用。

规模控制：这一步之后智能体不读任何 pdf 全文；子会话只读 digest，需要细节时按页码标记回查 papers_txt。

### 3.4 图表提取（第 3 步开跑项）

```
node scripts/review.mjs figures --project <项目目录> [--id <编号>]
```

对每篇有 pdf 存档的条目自动提图（位图直提 + 矢量图感知：纯矢量图走 caption 窗口裁剪或整页兜底，位图+矢量混排复合图按碎片并集∪邻近矢量簇裁剪），产物 `figures/{id}_{slug}/fig_N.png` + `manifest.json`（逐图记录页码、来源、图注）。单图来源分四类（manifest `origin` 字段）：内嵌直提（原生分辨率，质量最高）、内嵌直提（已自动转正，侧躺位图自动旋转）、渲染裁剪（碎片拼图 / 图注定位裁剪，建议人工过目）、整页截取（整页高清图，供手动裁剪）。跑完按来源汇总报告，渲染裁剪与整页截取的条目提示人工过目。

**整页兜底红线**：提不出真图（扫描版条带 / 矢量图）或自动裁剪产物实为文字段时，**不放假图**——退化为图表所在页的整页高清截取，manifest 标注。用户手动裁剪流程：裁剪替换对应 `fig_N.png` → 在 md 中更新引用（可去掉「整页截取」标注）→ 重跑第 5 步 HTML 导出（§5.4），不回跑其他步骤。执行细节（决策树分支、两段进程隔离架构、扫描件与双栏 OCR 的已知边界）见 `references/delivery-playbook.md`。

时机：获取完成停点拍板后、精读派发前跑一次（条目与综述都可配图）；补拉新篇后对单篇 `--id` 补跑。依赖见 §1 适配表；首次使用前先装依赖。

**获取完成 → §0 停点 2**：汇总获取台账向用户报告并问 A/B，拍板前不进 §4。

## 4 精读条目（并行阶段）

```
node scripts/review.mjs init-summaries --project <项目目录>
```

按清单初始化全部条目模板（`read_status: missing`）。之后每篇条目的产生方式：

**有子会话能力：一次派一篇。**

**会话策略：一篇一会话。** 每篇用适配表「子会话派发」能力独立创建一个一次性隔离会话（运行完即归档，不复用），会话标识记入派发台账；一篇会话只处理一篇，回收完成后不再复用于其他篇（上下文不跨篇残留）。对该篇返回内容有疑义时，向同一会话续投追问（续投能力同见适配表），篇内上下文仍在、免重读；疑点解决后继续回收。禁止同一子会话顺序处理多篇。

**并发策略：完成事件驱动排队。** 同时活跃子会话数按停点 2 问询的档位执行（标准档 = 2）：从待派队列取篇派发，收到完成事件并回收后，才从队列补派下一篇——不一次性派满。批量派发前用 `dispatch` 子命令生成任务单（`deliverables/dispatch.md`，含待派队列与每篇任务卡全文），主会话照单派发，不为单篇现编任务卡结构；派发台账记每个 childSessionKey 与回收状态，宿主报并发上限时失败件排队待补，不放弃、不缩任务卡。

任务卡要素：

1. 输入 = `digests/{id}.md`（必读）+ `papers_txt/{id}.txt`（仅定向回查，不整读）+ digest 尾部图题索引 + `digests/{id}.figs.md`（需要图意时读）。
2. 上下文 = 综述核心问题与用户敲定的重点 + 章节骨架 + 本篇 `read_depth`（子会话带着综述问题读；核心问题按主会话对话中的最新意图提炼，不照抄初始问句）。
3. 任务 = 按 `references/条目字段契约.md` 填条目。
4. 硬约束 = 只写读到的内容、证据链必填、`read_status` 按实际深度申报（只读到摘要就报仅摘要，禁止拔高）、附 `depth_reassessment`（对预判深度的二次评估：维持/升级/降级 + 一句理由）。
5. 落盘 = `node scripts/review.mjs save --project <项目目录> --id <编号>`（stdin JSON，先落盘再返回）。中文必须经执行工具的 stdin 直传能力传入；宿主仅支持 shell 管道时，管道首句必须显式设 UTF-8 输出编码，且落盘后必须统计 `?` 数与中文字符数验证中文完好——管道默认编码会把中文静默替换为 `?`，校验通过也不代表中文无损。
6. 返回一行 = 编号、阅读深度中文含义、二次评估结论、条目路径。

**深度二次评估裁决**：条目按实际内容修正预判——读完发现对核心章节论证关键的可升级（升级后按升级后深度补读对应章节再定稿），边缘的降级。全文已读篇数设预算上限（默认清单的 20%，可在停点 2 与用户确认放宽——短文密集的清单实际成本远低于厚专著，如实申报优先于预算）：子会话升级只申报建议；主会话汇总全部升级建议后统一裁决。裁决依据 = 返回行内的升级理由 + `digests/keyfacts.md` 查段，禁止为裁决逐篇开条目全文；理由与 keyfacts 相互矛盾时才开对应条目抽查。超预算的维持原深度并在台账留档。

**无子会话能力：** 主会话按同一任务卡逐篇顺序处理，其余不变。

阅读深度对应读法（清单 `read_depth` 提示，条目按实际申报与二次评估修正）：brief＝只读摘要（仅摘要）；targeted＝digest + 定向回查（部分精读或全文已读，按实际覆盖）；full＝通读 papers_txt 全文（全文已读）。

回收与重试：主会话按 `summaries/summary_{id}.json` 存在且 `validate` 通过判定完成；失败只重派该篇。全部完成后跑：

```
node scripts/review.mjs validate --project <项目目录>
node scripts/review.mjs brief --project <项目目录>
```

`brief` 产出每篇 ≤320 字的路由简报 `digests/brief.md`——主会话此后了解全貌只读它，不再逐条重读条目。`validate` 有 error 时回改对应条目重跑：单篇 error 主会话直接开该条目小修（条目为 KB 级文件，读取可控）；3 篇及以上成批 error 派子会话按 error 清单修，主会话不逐篇开条目。

**精读→成文自动续跑（不设人工停点）**：批量精读全链路只读本地落盘文件（`digests/{id}.md` + `papers_txt/{id}.txt` + 图题索引，零 URL 访问），回收完成 → `validate` → `brief` → 0 error 即直接进 §5，不等用户回「继续」；有 error 按上文处置回改，回改完成同样自动续跑。停下只发生在两种情况：①error 回改修不动（子会话重派仍失败）；②成文阶段补拉循环触发需人守的渠道（§5.2）——这两类停点都是天然卡点，停下时写清卡点与建议动作，等用户一句话续跑。适合夜间无人值守执行：低并发精读耗时数小时，停点 2 拿到档位与清单冻结后即可挂机，次日直接看综述初稿。

## 5 综述成文（章节文件化）

### 5.1 素材包

```
node scripts/review.mjs material --project <项目目录>
```

从通过校验的条目生成 `review-material.md`（带 `[编号]` 锚点、阅读深度、证据链、首条指标；仅摘要条目附英文摘要节选供转述；超长字段按上限裁剪）。带 error 的条目不进素材包并在包头列出——它们的问题会污染全篇综述。素材包是综述写作时数字与结论的唯一合法来源。

### 5.2 写作纪律（按章节写文件）

综述按章节落盘 `deliverables/sections/{NN}_{章节名}.md`，骨架用 `templates/review-template.md`（背景与问题、领域全景与分类、方法与技术路线、关键结果与性能对比、范式演进、局限与挑战、未来方向、对用户研究的相关点、文献映射）；全部章节完成后拼装：

```
node scripts/review.mjs assemble --project <项目目录> --out <综述.md>
```

写综述时只准读素材包，需要复核单篇时按编号重开那一个条目。硬规则：

- 每个论断后缀 `[编号]`；素材包里没有的数字禁止出现。
- 「仅摘要」的论文只可转述摘要级信息；「未获取」的不得在正文引用。
- 指标横向对比先判口径可比性（体系、条件、指标定义），不可比就写差异，不硬比大小。
- 前瞻判断与共性归纳凡超出素材包字面的，标注「（综述者判断）」。
- 章节写完即落盘放手；不回读已写章节全文，跨章呼应靠骨架与各章首尾段，需要衔接时只读相邻章节的末尾与开头。
- 含上标 Unicode（cm⁻¹、10⁵ 类）或带圈数字的章节，落盘后必须抽查漂移——上标字符可能被静默写成「的 5 次方」类文字；grep「次方」「上标」残留可定位。
- 文献映射章用 `map` 子命令生成（`deliverables/sections/09_文献映射.md`；条目定收录、题录定作者），出错整体重跑，不做正则二次补丁。
- 「对用户研究的相关点」章节先读宿主用户信息文件取课题；无课题信息先问一句，问不到改写通用切入点并声明。
- 综述配图引用 `figures/{id}_{slug}/fig_N.png` 相对路径；来源为整页截取的图，图注后标「（整页截取，可手动裁剪）」；用户手动裁剪替换后更新或删除该标注。

**补拉循环**：写作中发现缺口 → 缺口清单落盘 → ≤3 篇且①②③档可解的当场补；>3 篇或需④档的停下问用户 → 补到后只重写涉及章节 + 重新拼装，不全篇重写。补拉新篇的精读与条目落盘同样按 §4 任务卡派子会话，主会话不亲读新篇全文；重写涉及章节与重拼装由主会话做（全篇口径在主会话侧）。版本演进上限：初稿 → 补全版 → 终稿；再要大改应重开项目。

### 5.3 交付自检（派子会话）

拼装完成后把交付自检派给子会话：子会话跑 check、按结果回改并重跑至 0 FAIL，主会话只收一行结论，不亲跑回改循环。

```
node scripts/review.mjs check --project <项目目录> --review <综述.md>
```

（check 缺省读 `deliverables/综述.md`，与 assemble 缺省输出同名，缺省名下 `--review` 可省；assemble 用了自定义 `--out` 时，check 必须带同名 `--review`。）

子会话任务卡：

1. 输入 = 拼装后的综述路径 + `review-material.md`。
2. 任务 = 跑 check；0 FAIL 则回报一行结论（几篇入库、几篇仅摘要、综述在哪、校验结论）。
3. FAIL 处置 = 非法引用改成素材包内的正确编号或删句；缺章按 §5.2 写作纪律补写；文献映射缺项按素材包条目补齐；回改后重跑至 0 FAIL。
4. WARN 处置 = 确实超出素材包字面的前瞻判断处补「（综述者判断）」；整章均为字面转述时不标注合法，回报中说明。
5. 硬约束 = 回改只准依据素材包；回改一律改 `deliverables/sections/` 对应章节源文件后重跑 assemble 与 check，不直接改拼装稿（防源文件与终稿脱节）；「对用户研究的相关点」章缺失不代写，交主会话补（用户课题信息在主会话侧）；素材包内容修不了的句子删掉并列入回报；拿不准的改动列出交主会话裁决。
6. 返回一行 = 校验结论 + 回改处数 + 删句清单（若有）。

无子会话能力：主会话按同一任务卡自行执行，其余不变。

check 规则：综述中所有 `[编号]` 必须存在于素材包（代码块与链接内的方括号自动剔除）；另做交付自检——章节齐全性（`report.optional_sections` 可豁免裁剪章节）、文末文献映射与素材包一致、前瞻判断章「（综述者判断）」标注存在性（缺失仅警告）。0 FAIL 才交付。交付正本为拼装后的综述 MD；自包含 HTML 交付走 §5.4（第 5 步），交稿 docx 等格式用宿主文档能力转换，转换后抽查数字与 MD 一致。收尾汇报说人话，不念内部字段名。

### 5.4 一键自包含 HTML 导出（第 5 步）

```
node scripts/review.mjs export-html --project <项目目录> [--review <综述.md>]
```

把综述 md 转为**单文件自包含 HTML**（同名 `.html`）：图片按 md 里的相对路径（`figures/...`，以**项目根**为基准解析，与 §3.4 配图纪律一致）自动 base64 内嵌，CSS 内嵌，零外链，离线可开；CLI 直跑引擎脚本时以 md 所在目录为基准。产物自检两条：图片内嵌数与 md 引用数一致；缺失图片列出清单（退出码非零，修正后重跑本步即可）。

**独立可重入是本步的设计核心**：只依赖综述 md 与其引用的本地图片文件。用户说「重新导出 HTML」「重新执行第五步」「我修正了图片，请重新导出」——只跑本步命令，不回跑精读、成文与自检。典型循环：第 5 步导出 → 用户手动裁剪整页图并更新 md → 再次触发第 5 步 → 交付终稿。

局限声明：不引 KaTeX／mermaid 等 CDN，保证离线可开，公式按 md 原样显示；需要公式渲染的场合走宿主文档能力转换交稿格式。

## 6 不要做什么

- 不在清单确认前下载或派读；不把候选清单当已确认清单；冻结后不扩池（走补拉循环）。
- 不把「仅摘要」写成「全文已读」，不给不出证据链的条目放行。
- 不在综述里引用素材包外的数字，不凭印象补引用编号。
- ④档渠道不开，除非用户对具体渠道显式授权；③档只认项目配置白名单，白名单外不自动。
- 不静默吞掉核验不符：题录对不上就停下修正，不将错就错。
- 不全篇重写可增量更新的综述；补拉循环外的大改先问用户。
- 工具失败如实申报：同一会话第一次换替代方案，第二次停手请示，不硬试第三次。
- 第 5 步重导出不回跑其他步骤；带缺失图片的 HTML 不当完成交付（缺失清单必须交用户）。
- 提图不放假图：自动产物为文字段或空白时不得混入图集，走整页截取兜底并在 manifest 如实标注。
